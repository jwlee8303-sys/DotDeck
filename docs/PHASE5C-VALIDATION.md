# Phase 5c 확인 절차

상태: 자동 테스트 완료, 실제 모델을 사용하는 아래 4개 시나리오는 사용자 수동 확인 대기.
브랜치: `feat/ai-cli-5c`. 기준 main은 `36651f4`(v1.3.0). 버전 변경·커밋·푸시는 하지 않았다.

## 준비

1. 임시 홈과 별도 테스트 프로젝트 두 개를 만든다. 실제 설정·인증서·비밀 파일을 복사하지 않는다.
2. 다음 명령으로 실행한다.

   ```powershell
   dotnet run --project src/DotDeck.App -- --home D:\tmp\dotdeck-5c-home
   ```

3. 테스트 폴더를 `문서 실험`, `웹게임` 프로젝트로 등록한다. 각각 `README.md` 같은 가짜 문서와 하위 폴더를 만들고 직접 개수를 기록한다. 기본 제외 폴더(`node_modules` 등)와 표시 필터에 숨길 파일도 둔다.
4. Claude·Codex 로그인은 이 임시 홈에서만 사용자가 진행한다. 샌드박스 PowerShell 터미널은 `CLAUDE_CONFIG_DIR`과 `CODEX_HOME`을 전달한다. 실제 사용자 홈의 인증 파일을 조사하거나 복사하지 않는다.
5. 도구 > **AI 세션 시작**(Ctrl+Alt+C)에서 CLI와 주·추가 프로젝트를 고른다. 프로젝트 우클릭에는 Claude·Codex 대화형 빠른 시작이 있다. 여러 프로젝트를 한 세션에서 다루려면 시작 화면의 추가 프로젝트를 체크한다.

Codex 비대화형은 임시 Codex 홈의 `config.toml`에서 명시적인 `[windows] sandbox = "elevated"` 또는 지원되는 모드가 확인되어야 선택할 수 있다. 설정 감지는 완료된 OS 프로비저닝까지 보장하지 않는다. Codex 자체 설정 절차로 준비한 뒤 사용한다. 미설정 대화형 실행은 경고 확인이 필요하다.

## 경로 없이 실행할 4개 시나리오

각 시나리오는 Claude와 Codex를 구분해 결과를 기록한다. 경로는 프롬프트에 넣지 않는다.

| 시나리오 | 준비·프롬프트 | 확인할 결과 |
|---|---|---|
| 열린 파일 수정 | `문서 실험/README.md`를 열고 한 문장을 선택한다. “활성 파일에서 선택한 문장을 더 짧게 수정해줘.” | `get_active_document`로 활성 파일·선택 영역을 확인하고 정확한 파일을 수정한다. 열린 편집기가 외부 변경을 반영하며 변경 검토에 diff가 표시된다 |
| 특정 프로젝트에 생성 | 두 프로젝트를 범위에 포함한다. “웹게임 프로젝트에 PLAY.md를 만들고 게임 실행 방법 예시를 써줘.” | `list_projects`의 이름↔루트로 `웹게임`을 선택하고 해당 폴더에만 생성한다 |
| md 개수 | “현재 범위 프로젝트에서 표시되는 md 파일이 모두 몇 개인지 알려줘. 프로젝트별로도 알려줘.” | `find_files`에 `*.md`를 사용한다. 제외 폴더·숨긴 파일·비밀 파일은 제외한다. 중복 경로를 제거한다. `truncated` 또는 `incomplete`면 전체 개수로 단정하지 않는다 |
| 파일 분석 | 서로 다른 프로젝트에 같은 이름의 README를 둔다. “README를 읽고 개선할 점을 알려줘.” | 활성 문서 프로젝트를 우선하며, 특정할 수 없으면 후보를 제시한다. 분석할 때 실제 내용을 읽고 필요하면 `open_in_editor`로 연다 |

## 보안·수명 확인

- 비밀 파일은 가짜 `auth.json`, 가짜 인증서 이름 등으로만 테스트한다. 내장 MCP의 문서·검색 결과와 편집기 열기에서 제외되어야 한다. 링크 최종 대상이 범위 밖·비밀인 경우도 제외한다.
- 열린 문서 전달을 끄면 초기 컨텍스트와 MCP의 열린·활성 문서 조회에 문서가 나타나지 않아야 한다.
- Claude에서 외부 사용자 MCP 호출은 확인 요청, 비대화형은 `--strict-mcp-config`로 세션 MCP만 로드한다.
- Codex는 `list_projects`·`find_files` 조회가 `approval policy is never`로 거부되지 않아야 한다. 범위 검사를 하는 DotDeck 내장 도구 5개만 `approval_mode="approve"`로 연결하고, 서버의 다른 도구 기본값은 `prompt`로 둔다. 모델 응답 생성 자체와 파일 수정 성공은 구분한다. 실패한 명령·파일 변경은 작업 패널에서 오류로 보여야 한다.
- 추가 프로젝트 제외 후 Claude의 다음 파일 호출과 MCP 결과에서 해당 프로젝트가 사라져야 한다. 실행 중인 MCP 호출의 결과도 폐기된다. Codex는 범위를 줄이면 중지되고 새 범위로 재시작해야 한다.
- Codex 대화형은 새 대화만 지원한다. 비대화형 종료 후 같은 범위에서 이어가기를 선택하면 기록된 thread ID를 사용한다.
- 내장 MCP의 제한과 Codex 네이티브 도구의 보호는 다르다. Codex는 `workspace-write` sandbox와 사후 변경 검토를 사용하며 Claude 훅의 비밀 파일 차단·범위 밖 읽기 차단을 제공하지 않는다.
- 변경 검토 수락 또는 종료 세션 목록 지우기/터미널 닫기가 정리 대상 표시를 만든다. 다음 앱 시작 시 7일 경과 또는 최근 20개 초과 세션을 정리한다. 실행 중인 세션(다른 앱 인스턴스 포함), 미검토 세션, 링크가 포함된 폴더는 보존한다.
- 통합 설정에서 테스트 파일을 자동백업 목록에만 등록하면 백업은 생성되지 않고 변경검토에는 남아야 한다. 변경검토 목록에만 등록하면 백업은 가능하고 검토·되돌리기에서 빠져야 한다. 폴더 등록은 하위 항목까지 적용하고 같은 접두사의 형제 폴더에는 적용하지 않는다. 기존 CLI 전용 제외 목록은 제거했으므로 자동으로 숨겨지는 시스템 경로는 없다.
- 저장 전 미리보기의 "백업 제외" 체크는 자동백업 목록에 즉시 저장되고, 등록 중에 저장을 눌러도 제외 저장 완료를 기다려야 한다. AI 변경검토의 "검토 제외" 체크는 해당 행을 목록에서 제거하며 두 목록이 서로 영향을 주면 안 된다. 기존 백업은 유지한다.

## 자동 검증 범위

- `McpTests`: 프로토콜 초기화·오류·알림·메시지 크기 제한, 결과 마스킹, 범위·비밀·최종 경로·표시 규칙, 범위 축소·종료
- `McpBridgeTests`: 실제 WinExe stdio↔Named Pipe 한글 왕복·정상 EOF 종료, 위조 인증 차단, DPAPI 키 저장
- `AiTerminalPaneTests`: 도구 실행 중 범위 변경 시 결과 폐기와 종료 후 호출 거부
- `AiSessionManagerTests`: Codex thread 저장·이어가기, heartbeat 독립성, 범위 축소 시 중지, MCP 수명·실행 실패 시 자원 해제
- `CodexAndRetentionTests`: JSONL 마스킹·잘못된 이벤트·본문 숨김, Windows sandbox 설정 파싱, 세션 보관 기간·개수·실행 중 제외
- `SessionLaunchViewModelTests`: Codex 선택, sandbox 미설정 비대화형 비활성, 대화형 이어가기 거부

실제 Claude/Codex의 로그인·모델 응답·TUI·사용자 MCP 승인 화면은 자동 테스트로 대체하지 않았다.
