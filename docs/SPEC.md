# DotDeck — 개발 사양서 v2 (Claude Code 작업 지시)

## 0. 너의 역할과 진행 방식
- 너(Claude Code)는 설계·구현 담당이다. 전역 CLAUDE.md 규칙(Codex 교차 검증, Conventional Commits, SemVer)을 따른다.
- 아래 Phase 순서대로 진행한다. **각 Phase가 끝나면** 빌드 → 테스트 → `/codex-review` → 커밋 → 결과 보고를 한 뒤, 내 확인을 받고 다음 Phase로 넘어간다.
- 시작 전에 `/project-init`으로 프로젝트를 세팅하고(버전 0.1.0), `architect` 에이전트로 전체 설계안을 만들어 내게 보여준다. 설계 승인 전에는 코드를 작성하지 않는다.
- 모호한 요구사항은 추측하지 말고 Phase 0에서 질문 목록으로 정리한다.
- **현재 상태:** Visual Studio로 `DotDeck.slnx`와 `DotDeck\` 프로젝트를 만들어 두었으나, 이 프로젝트는 WPF 앱이 아니라 **클래스 라이브러리 템플릿**(`Class1.cs`)이다. Phase 0 설계안에 이것을 정리하고 3절 구조(WPF 앱 + Core 라이브러리 + 테스트)로 다시 구성하는 계획, `TargetFramework`를 `net10.0-windows`(App) / `net10.0`(Core)로 맞추는 계획을 포함한다. 솔루션 파일은 `.slnx`를 유지한다.

## 1. 제품 개요
**DotDeck**은 개발 환경 설정 파일과 문서를 **하나의 창**에서 찾고·보고·수정·생성·삭제하는 Windows 데스크톱 에디터다.
흩어진 파일 위치를 사용자가 기억하지 않아도 되게 하는 것이 핵심 가치다. 개인 개발용 도구이며 네트워크 통신·텔레메트리는 없다.
UI와 사용감은 **Visual Studio 2022(다크 테마)** 를 기준으로 한다: 도킹 가능한 패널, 문서 탭, 솔루션 탐색기형 트리.

## 2. 핵심 개념: 프로젝트 = 탐색기
- **프로젝트**는 "이름 + 루트 폴더(또는 가상 소스)"의 묶음이고, 프로젝트 하나마다 **탐색기(폴더 트리) 하나**가 있다.
- 탐색기는 여러 개가 동시에 열린다. 모든 탐색기는 화면 왼쪽의 **"프로젝트" 영역**에 모여 있다.
  - 기본 배치: 프로젝트 영역 안에 탐색기들이 위아래로 쌓인 접이식 섹션(각 섹션 헤더에 프로젝트 이름).
  - 각 탐색기는 **별도 패널로 떼어내기**(도킹 위치 이동·플로팅) 및 다시 프로젝트 영역으로 붙이기가 가능하다.
- 앱을 켜면 등록된 프로젝트가 **자동으로 열리고**, 마지막 트리 펼침 상태·선택 위치가 복원된다.

### 2.1 기본 제공 프로젝트 (삭제 불가, 숨기기·순서 변경 가능)
| 이름 | 루트 | 설명 |
|---|---|---|
| Claude 전역 | `%USERPROFILE%\.claude\` | CLAUDE.md, settings.json, agents, skills, commands, rules, output-styles (역할은 7.0 판별기가 결정) |
| Codex 전역 | `%USERPROFILE%\.codex\` | AGENTS.md, config.toml |
| 시스템 | (가상 트리) | `환경변수(사용자)`, `환경변수(시스템)`, `PATH`, `중요 파일`(8절) 노드로 구성 |
- 루트 폴더가 없으면 트리에 "폴더 없음 — 만들기" 안내를 표시한다.

### 2.2 사용자 프로젝트
- "프로젝트 추가" 대화상자: **프로젝트 이름 + 폴더 선택** → 생성. 선택: 아이콘 색상, 표시 필터.
- 예: `DotDeck` → `D:\project\DotDeck`, `웹게임` → `D:\project\webgame`.
- 프로젝트 제거는 목록에서만 빠지고 디스크 파일은 건드리지 않는다. 이름·루트 변경 가능.
- 프로젝트 정의는 `%APPDATA%\DotDeck\projects.json`에 저장한다.

### 2.3 탐색기 기능
- **위치 확인 버튼**(탐색기 헤더 툴바): 루트 경로 복사, Windows 탐색기에서 열기, 현재 선택 항목으로 트리 동기화(열린 문서 ↔ 트리 위치), 모두 접기, 새로고침.
- 상단 경로 표시(breadcrumb)로 선택 항목의 전체 경로를 항상 보여준다.
- **트리 직접 조작:** 새 파일, 새 폴더, 이름 바꾸기(F2), 삭제(휴지통, Del), 복사·잘라내기·붙여넣기, 복제, **드래그 앤 드롭 이동**(같은 프로젝트 내·프로젝트 간), 다중 선택.
- 컨텍스트 메뉴: 위 작업 + 경로 복사(절대/상대), 탐색기에서 열기, VS Code로 열기, 여기서 터미널 열기(Windows Terminal/PowerShell), 템플릿으로 새로 만들기(6절).
- **표시 필터**(프로젝트별 토글): `모든 파일` / `설정·문서만`(md, json, jsonc, toml, yaml, yml, ps1, py, cs, xaml, props, txt). 사용자 프로젝트 기본값은 `설정·문서만`.
- 제외 폴더(기본, 설정 가능): `node_modules`, `bin`, `obj`, `.git`, `.vs`, `.venv`, `dist`, `__pycache__`.
- 아이콘으로 파일 종류 구분, 미저장 문서 표시(●), 검증 오류 표시(⚠).
- 파일 시스템 변경은 `FileSystemWatcher`로 트리에 실시간 반영(디바운스).
- 이동·이름 바꾸기·삭제는 **작업 이력**에 기록되어 "되돌리기"(탐색기에서 Ctrl+Z)가 가능하다. 삭제는 휴지통에서 복원.
- 비밀 파일(`.env*`(example 제외), `*.pfx`, `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`)은 트리에 자물쇠 아이콘으로 표시하고 열지 않는다.
- 파일을 열 때 7.0 판별기가 역할·범위를 정하고, 탭 툴팁과 속성 패널에 `역할 · 범위`(예: `settings.json · 프로젝트`)를 표시한다.
- 컨텍스트 메뉴와 문서 탭 메뉴에 "다음 형식으로 열기 ▸ 텍스트/Markdown/설정 폼/에이전트 폼/스킬 폼/자동 판별로 되돌리기"를 둔다. 지정은 파일 경로별로 `%APPDATA%\DotDeck\editor-overrides.json`에 기억한다. 폼이 내용을 해석하지 못하면 이유를 표시하고 텍스트 보기로 연다.

## 3. 기술 스택과 구조
- .NET 10 (LTS), WPF, C# (Nullable enable)
- MVVM: CommunityToolkit.Mvvm
- **도킹 레이아웃: Dirkster.AvalonDock + VS2013 테마 패키지** (VS 다크 테마 기반, 설계에서 대안이 더 낫다면 비교 후 제안)
- 텍스트 편집: AvalonEdit (Markdown/JSON/TOML/YAML/Python/PowerShell/C#/XAML 구문 강조, 찾기/바꾸기, 줄 번호)
- Markdown 미리보기: Markdig → WebView2 (설계에서 FlowDocument와 비교 후 확정)
- Diff: DiffPlex / 테스트: xUnit
- 배포: `dotnet publish -c Release -r win-x64 -p:PublishSingleFile=true`
- 위 외의 NuGet 패키지는 추가 전에 이유를 설명하고 승인받는다.

```
DotDeck.slnx
Directory.Build.props          (Version, Nullable, LangVersion)
src/DotDeck.Core/              UI 의존성 없음: 프로젝트 모델, 파일 작업·작업 이력, 파서, 검증기, 환경변수 추상화
src/DotDeck.App/               WPF: Shell(도킹), 탐색기, 에디터, 테마, ViewModel
tests/DotDeck.Core.Tests/      xUnit
docs/                          SPEC.md, 설계 문서
```
- 실제 파일 시스템, 레지스트리, 환경변수 접근은 인터페이스(`IFileStore`, `IEnvironmentStore` 등) 뒤에 둔다. 테스트는 임시 폴더와 가짜 구현만 사용한다.
- **개발·테스트 중에 내 실제 `~/.claude`, `~/.codex`, 환경변수, hosts 파일을 수정하지 않는다.** `DOTDECK_HOME` 환경변수(또는 실행 인자 `--home <dir>`)로 기본 제공 프로젝트의 홈 경로를 바꿀 수 있게 하고, 수동 테스트는 이것으로 한다.

## 4. 화면과 레이아웃 (도킹)
- **메뉴바**: 파일 / 편집 / 보기 / 프로젝트 / 도구 / 창 / 도움말. **툴바**: 새로 만들기, 열기, 저장, 모두 저장, 실행 취소/다시 실행, 전역 검색 상자.
- **왼쪽: 프로젝트 영역** (2절의 탐색기들). 폭 조절, 자동 숨김(핀) 가능.
- **가운데: 문서 영역**
  - 여러 문서를 탭으로 연다. 탭 고정(pin), 미리보기 탭(한 번 클릭 시 임시 탭, VS 방식), 탭 드래그로 순서 변경.
  - **분할:** 탭을 끌어 가로/세로 탭 그룹 생성, 여러 그룹 동시 표시.
  - **플로팅:** 문서 탭을 창 밖으로 끌어내 독립 창으로 띄우기(다중 모니터), 다시 도킹.
  - 같은 파일을 두 그룹에서 동시에 보기(같은 버퍼 공유).
- **오른쪽: 속성 패널** (선택 항목 정보, 검증 결과, 빠른 작업).
- **아래: 출력 패널 탭** — `출력`(작업 로그), `검증 결과`, `검색 결과`, `훅 테스트`.
- 모든 패널은 도킹 위치 변경·플로팅·자동 숨김 가능. 레이아웃은 종료 시 저장, 시작 시 복원. `창 → 레이아웃 초기화`, 이름 붙인 레이아웃 저장/불러오기.
- **상태줄**: 현재 문서 경로·인코딩·줄바꿈·커서 위치, 관리자 권한 여부, 마지막 백업 위치.
- 단축키는 VS 관례를 따른다: Ctrl+S, Ctrl+Shift+S(모두 저장), Ctrl+F/H, Ctrl+Shift+F(전역 검색), Ctrl+Tab(문서 전환), Ctrl+F4(탭 닫기), F2(이름 바꾸기).

## 6. 안전한 파일 편집 (모든 쓰기 공통)
- 저장 전 **diff 미리보기** 대화상자 (설정에서 끌 수 있음, 기본 켬).
- 저장 시 원본을 `%LOCALAPPDATA%\DotDeck\backups\<yyyyMMdd-HHmmss>\<원래 경로 구조>`에 백업. 백업 목록에서 복원. 보관 개수 설정(기본 50).
- 원자적 쓰기(임시 파일 → 교체). 기존 인코딩(BOM 유무)과 줄바꿈(CRLF/LF) 보존.
- 외부 변경 감지 → 미저장 변경이 있으면 "다시 불러오기 / 내 버전 유지 / diff 보기".
- 대용량 파일(1MB 초과)은 열기 전 경고. 바이너리 파일은 열지 않고 정보만 표시.
- 새로 만들기 템플릿: 에이전트, 스킬(폴더+SKILL.md), 훅 스크립트(Python), 프로젝트 CLAUDE.md(web/csharp/python). 템플릿은 `%APPDATA%\DotDeck\templates\`에 두고 앱에서 수정 가능.

## 7. 타입별 전용 편집기
문서 탭 상단에서 `텍스트 | 미리보기 | 폼 | 분할` 보기를 전환한다(해당 타입만).
### 7.0 파일 역할 판별
- 파일 이름이 아니라 Claude Code가 설정을 읽는 위치로 판별한다. 가장 가까운 `.claude` 폴더 기준 상대 경로 → `.claude` 밖 규칙(CLAUDE.md, CLAUDE.local.md, .mcp.json, ~/.claude.json 등) 순서. `.claude`의 부모가 홈(`DOTDECK_HOME`/`--home` 해석 결과)이면 전역, 아니면 프로젝트. `settings.local.json`은 로컬(Git 제외).
- `.claude` 밖 프로젝트 파일은 "앵커 폴더"(`.claude` 또는 `.git`이 있거나 등록된 프로젝트 루트) 기준으로 판별한다. 앵커가 아닌 폴더의 CLAUDE.md는 "하위 폴더"(필요 시 로드) 범위.
- 규칙은 `DotDeck.Core/Catalogs/<제품>/file-roles.json` 데이터로 관리한다(제품 단위로 확장, Codex는 이후).
- 파일 내용은 보조 신호로만 쓴다. 기본 제공 프로젝트와 사용자 프로젝트에 같은 판별기를 쓴다.
### agents/*.md (`.claude/agents/` 아래, 하위 폴더 포함)
- 폼: `name`, `description`(여러 줄), `tools`(체크 목록 + 직접 입력, 도구 카탈로그 공유), `model`(opus/sonnet/haiku/fable/inherit/직접 입력) + 본문.
- 검증: frontmatter 파싱, `name`·`description` 필수(`name`이 없으면 Claude Code는 문서로 취급). 파일명과 다르면 정보 표시.
### skills/<이름>/SKILL.md (`.claude/skills/` 아래)
- 폼: `name`, `description` + 본문. 검증: `name`은 선택(없으면 폴더명), 폴더명과 다르면 경고, `description`+`when_to_use` 1536자 초과 경고.
### settings.json (전역/프로젝트/로컬)
- **권한 탭**: 행 = `[allow|ask|deny] [도구(선택+직접 입력, 기본 도구+MCP)] [인수]`. 저장할 때 `도구(인수)`, 인수가 없으면 `도구`. 해석할 수 없는 규칙은 원문 그대로 표시·보존. 도구별 인수 작성법(placeholder·규칙·예시·함께 적용되는 도구, `/path`의 범위별 기준)을 툴팁과 속성 패널에 한글로 표시. 행 추가·삭제·이동, 중복·충돌 경고와 무효 규칙 경고.
- **훅 탭**: 이벤트 드롭다운(Claude Code 훅 이벤트 전체 + 직접 입력, 모르는 값 보존), 이벤트 설명(실행 시점·matcher 사용 여부·할 수 있는 일·사용 예). matcher는 체크 목록(도구 또는 이벤트별 값, MCP)·전체·정규식(오류는 경고만). matcher를 쓰지 않는 이벤트는 칸 비활성화(기존 값 보존). `type`이 command가 아닌 훅도 보존. command, timeout 열.
- 스크립트 경로 존재 검증은 판별된 루트 기준(`$CLAUDE_PROJECT_DIR`·상대 경로는 프로젝트 루트, `~`는 홈). 해석할 수 없는 경로는 "확인 불가".
- **MCP 서버 탐색**: 사용자·로컬(`~/.claude.json`), 프로젝트(`.mcp.json`), 설치된 플러그인 설정을 읽기 전용으로 파싱해 서버 이름과 출처만 표시. 서버 실행·연결 안 함. 새로고침.
- **범위 경고**: 해당 범위에서 무시되거나 의미가 달라지는 키를 안내.
- 도구·이벤트·키 설명은 `Catalogs/Claude/*.json`(공식 문서 주소·확인 날짜 포함)으로 관리. `%APPDATA%\DotDeck\catalogs\`의 같은 이름 파일로 덮어쓸 수 있다.
- **훅 테스트 실행기**: 이벤트별 샘플 JSON(수정 가능)을 stdin으로 넣어 실행 → stdout/stderr/종료코드/소요시간을 `훅 테스트` 패널에 표시. 10초 타임아웃, 실행 전 확인.
- **환경 탭**: `env` 키-값 표.
- **JSON 모드**와 폼 양방향 동기화. 폼이 모르는 키는 반드시 보존. JSON 오류 시 폼 전환 차단.
### CLAUDE.md / AGENTS.md / 일반 md
- 편집 + 미리보기 분할 보기, 헤더 목차 탐색.

## 8. 시스템 프로젝트
### 환경변수
- 사용자/시스템 노드를 열면 **표 형태 문서 탭**으로 열린다. 검색, 추가, 수정, 삭제. 변경 전 diff, 변경 내역을 백업 폴더에 JSON으로 기록(되돌리기 가능).
- 이름에 `KEY|TOKEN|SECRET|PASSWORD|PWD|CREDENTIAL`이 포함된 값은 기본 마스킹, 눈 아이콘으로 표시. 로그·백업에도 평문을 남기지 않는다.
- **PATH 편집기**: 항목 목록, 위/아래 이동, 존재하지 않는 경로·중복 경고.
- 변경 후 `WM_SETTINGCHANGE` 브로드캐스트, "열린 터미널에는 적용 안 됨" 안내.
- 시스템(Machine) 범위는 관리자 권한일 때만 쓰기. 아니면 읽기 전용 + "관리자 권한으로 다시 시작"(열린 문서·레이아웃 복원). 앱 매니페스트는 `asInvoker`.
### 중요 파일
- 기본 목록(추가·제거 가능): `%USERPROFILE%\.gitconfig`, `.npmrc`, `.ssh\config`, PowerShell 프로필(`$PROFILE`), Windows Terminal `settings.json`, `C:\Windows\System32\drivers\etc\hosts`.
- 관리자 권한이 필요한 파일(hosts 등)은 환경변수와 같은 규칙. 비밀 파일은 목록에 추가할 수 없다.
### 권한 보기
- Claude Code 권한은 7절 settings 편집기에서 다룬다.
- Windows 파일/폴더 ACL은 속성 패널에서 **읽기 전용 보기**만 제공한다. ACL 수정 기능은 만들지 않는다.

## 9. 기타
- 전역 검색(Ctrl+Shift+F): 열린 모든 프로젝트 대상, 프로젝트·파일 형식 필터, 결과 더블클릭 시 해당 파일·줄로 이동.
- 앱 설정 화면: 백업 보관 개수, diff 미리보기 여부, 제외 폴더, 글꼴 크기, 테마, 외부 에디터 경로.
- 예외 처리: 모든 파일 I/O 실패는 원인과 경로를 출력 패널과 알림으로 보여주고 앱은 계속 동작.
- 로그: `%LOCALAPPDATA%\DotDeck\logs\` (비밀값 금지).

Phase 1 범위가 크므로 내부적으로 1a(셸·테마·도킹) → 1b(프로젝트·탐색기·트리 조작) → 1c(에디터·안전 저장·레이아웃 저장)로 나눠 각각 커밋하고, 1a가 끝나면 스크린샷 또는 실행 방법을 알려줘서 디자인을 중간 확인받는다.
