# DotDeck — 개발 사양서 v2 (Claude Code 작업 지시)

## 0. 너의 역할과 진행 방식
- 최신 원칙(2026-11-08): DotDeck은 관리자가 쓰는 최상위 개발 환경 도구다. 보안을 이유로 파일 열기·편집·저장을 막지 않는다. 비밀 파일도 열기·편집·백업·사용자 지정 파일 등록을 허용한다. **화면 값은 기본으로 평문 표시한다**(사용자가 자기 값을 못 볼 이유가 없다). **화면 공유 모드**(상태줄 버튼 + 보기 메뉴, 설정에 저장, 기본 끔)를 켰을 때만 비밀값을 가리고 눈 아이콘으로 보기마다 해제한다. 공유 모드에서 JSON/TOML 파싱이 실패하면 문서 전체를 가린다. 실제 유출 방지는 화면이 아니라 기록 쪽이다: 로그·출력 패널·백업 JSON·변경 기록·diff 요약·오류 메시지·예외 덤프에는 모드와 관계없이 비밀값 평문을 남기지 않는다(문서를 열고 저장할 때 비밀값을 수집해 필터에 등록). 비밀 파일 판정은 링크 체인(파일 링크·폴더 링크·정션)을 끝까지 따라간 최종 대상 기준이며, 하드링크는 구분하지 못한다. 백업은 DPAPI(CurrentUser)로 투명하게 암호화한다. 이 원칙이 아래 과거의 비밀 파일 금지·문서 잠금 문구보다 우선한다. 개발 중 실제 사용자 설정을 수정하지 않는 규칙은 유지한다.
- 너(Claude Code)는 설계·구현 담당이다. 전역 CLAUDE.md 규칙(Codex 교차 검증, Conventional Commits, SemVer)을 따른다.
- 아래 Phase 순서대로 진행한다. **각 Phase가 끝나면** 빌드 → 테스트 → `/codex-review` → 커밋 → 결과 보고를 한 뒤, 내 확인을 받고 다음 Phase로 넘어간다.
- 시작 전에 `/project-init`으로 프로젝트를 세팅하고(버전 0.1.0), `architect` 에이전트로 전체 설계안을 만들어 내게 보여준다. 설계 승인 전에는 코드를 작성하지 않는다.
- 모호한 요구사항은 추측하지 말고 Phase 0에서 질문 목록으로 정리한다.
- **현재 상태:** Visual Studio로 `DotDeck.slnx`와 `DotDeck\` 프로젝트를 만들어 두었으나, 이 프로젝트는 WPF 앱이 아니라 **클래스 라이브러리 템플릿**(`Class1.cs`)이다. Phase 0 설계안에 이것을 정리하고 3절 구조(WPF 앱 + Core 라이브러리 + 테스트)로 다시 구성하는 계획, `TargetFramework`를 `net10.0-windows`(App) / `net10.0`(Core)로 맞추는 계획을 포함한다. 솔루션 파일은 `.slnx`를 유지한다.

## 1. 제품 개요
**DotDeck**은 개발 환경 설정 파일과 문서를 **하나의 창**에서 찾고·보고·수정·생성·삭제하는 Windows 데스크톱 에디터다.
흩어진 파일 위치를 사용자가 기억하지 않아도 되게 하는 것이 핵심 가치다. 개인 개발용 도구이며 네트워크 통신·텔레메트리는 없다.
UI와 사용감은 **Visual Studio 2022(다크 테마)** 를 기준으로 한다: 도킹 가능한 패널, 문서 탭, 솔루션 탐색기형 트리.

## 2. 핵심 개념: 프로젝트 = 탐색기
- **프로젝트**는 "이름 + 루트 폴더(또는 가상 소스)"의 묶음이고, 프로젝트 하나마다 **탐색기(폴더 트리) 하나**가 있다.
- 탐색기는 여러 개가 동시에 열린다. 모든 탐색기는 화면 왼쪽의 **"프로젝트" 영역**에 모여 있다.
  - 기본 배치: 프로젝트 영역 안에 탐색기들이 위아래로 쌓인 접이식 섹션(각 섹션 헤더에 프로젝트 이름).
  - 각 탐색기는 **별도 패널로 떼어내기**(도킹 위치 이동·플로팅) 및 다시 프로젝트 영역으로 붙이기가 가능하다.
- 앱을 켜면 등록된 프로젝트가 **자동으로 열리고**, 마지막 트리 펼침 상태·선택 위치가 복원된다.

### 2.1 기본 제공 프로젝트 (삭제 불가, 숨기기·순서 변경 가능)
| 이름 | 루트 | 설명 |
|---|---|---|
| Claude 전역 | `%USERPROFILE%\.claude\` | CLAUDE.md, settings.json, agents, skills, commands, rules, output-styles (역할은 7.0 판별기가 결정) |
| Codex 전역 | `CODEX_HOME` 또는 `%USERPROFILE%\.codex\` | config.toml, hooks.json, agents, rules, AGENTS.md 및 가상 스킬 노드(7.5절). 샌드박스에서는 실제 CODEX_HOME 무시 |
| 시스템 | (가상 트리) | `환경변수(사용자)`, `환경변수(시스템)`, `PATH`, `사용자 지정 파일`(8절) 노드로 구성 |
- 루트 폴더가 없으면 트리에 "폴더 없음 — 만들기" 안내를 표시한다.

### 2.2 사용자 프로젝트
- "프로젝트 추가" 대화상자: **프로젝트 이름 + 폴더 선택** → 생성. 선택: 아이콘 색상, 기본 확장자(2.3).
- 예: `DotDeck` → `D:\project\DotDeck`, `웹게임` → `D:\project\webgame`.
- 프로젝트 제거는 목록에서만 빠지고 디스크 파일은 건드리지 않는다. 이름·루트 변경 가능.
- 프로젝트 정의는 `%APPDATA%\DotDeck\projects.json`에 저장한다.

### 2.3 탐색기 기능
- **위치 확인 버튼**(탐색기 헤더 툴바): 루트 경로 복사, Windows 탐색기에서 열기, 현재 선택 항목으로 트리 동기화(열린 문서 ↔ 트리 위치), 모두 접기, 새로고침.
- 상단 경로 표시(breadcrumb)로 선택 항목의 전체 경로를 항상 보여준다.
- **트리 직접 조작:** 새 파일, 새 폴더, 이름 바꾸기(F2), 삭제(휴지통, Del), 복사·잘라내기·붙여넣기, 복제, **드래그 앤 드롭 이동**(같은 프로젝트 내·프로젝트 간), 다중 선택.
- 컨텍스트 메뉴: 위 작업 + 경로 복사(절대/상대), 탐색기에서 열기, VS Code로 열기, 여기서 터미널 열기(Windows Terminal/PowerShell), 템플릿으로 새로 만들기(6절).
- **보이는 항목**(폴더 프로젝트별, 기본 제공 Claude·Codex 포함, 시스템 프로젝트 제외). 이전의 "표시 필터(모든 파일/설정·문서만)"를 대체한다.
  - **편집 모드**(헤더 ✎ 토글): 모든 항목을 3상태 체크박스(체크/해제/일부 ■)와 함께 보인다. 해제 항목은 흐리게 표시. 폴더를 체크하면 아래가 모두 체크되고, 이후 하위를 해제하면 부모는 일부(■). 해제된 폴더 아래에서도 개별 체크 가능. 기본 확장자가 아닌 파일은 폴더 체크와 관계없이 해제 상태이며 개별로 체크해야 보인다. 일부(■)를 클릭하면 체크. 루트 체크박스는 헤더에 있다.
  - **일반 모드**: 체크된 항목만 체크박스 없이 보인다. 보일 것이 없는 폴더는 숨긴다(자기 자신에 체크 규칙이 있는 폴더는 비어 있어도 보임).
  - **판정 순서**(Core, UI 의존 없음): ① 파일 자신의 규칙 → ② "모든 파일 보기"가 꺼져 있고 기본 확장자가 아니면 숨김 → ③ 가장 가까운 조상 폴더 규칙 → ④ 보임. 제외 폴더는 판정보다 먼저 빠진다(편집 모드에서도).
  - 규칙은 사용자가 바꾼 것만 `projects.json`(schemaVersion 2)의 `visibility.rules`에 상대 경로(`/` 구분) → `include`/`exclude`로 저장한다. 상속값과 같은 규칙은 저장하지 않는다. 폴더를 체크·해제하면 그 폴더 규칙만 남기고 아래 규칙은 지운다(직접 체크한 파일이 지워지면 "직접 체크한 파일 N개도 해제됩니다"로 확인).
  - 편집 모드를 끝낼 때와 앱을 닫을 때 저장한다.
  - 이름 바꾸기·이동·삭제(앱 안에서, 실행 취소·다시 실행 포함)는 규칙·고정·평면 순서를 따라 옮기거나 지운다. 새로 만들기·붙여넣기·복제·다른 프로젝트에서 옮겨 온 항목은 숨겨질 경우 자동으로 체크 규칙을 붙인다.
  - **기본 확장자**: 프리셋 `설정·문서`(md, json, jsonc, toml, yaml, yml, ps1, py, cs, xaml, props, txt) 체크 목록 + 직접 입력(`.LOG`, `log`, `*.log` → `.log`, `.d.ts`처럼 여러 마디도 가능, 파일 이름 끝 일치). "모든 파일 보기"는 목록을 비활성으로 두되 값은 보존한다. "전역 기본값 사용"(설정 대화상자의 탐색기 기본 확장자)이 새 프로젝트·기본 제공 프로젝트의 초기값이다. 확장자를 바꾸면 "직접 체크한 항목 유지 / 모두 기본값으로 초기화"를 묻는다.
- **일반 모드 보기**(프로젝트별 저장, 기본 압축 트리): 헤더 `트리 | 압축 | 평면`.
  - 압축 트리: 하위 폴더 하나뿐인 폴더 사슬을 한 줄(`src/DotDeck.App/Themes`)로 합친다. 각 마디를 클릭하면 그 폴더가 명령 대상이 된다. 자기 체크 규칙이 있는 폴더·링크·고정 항목에서 사슬이 끊긴다.
  - 평면: 보이는 파일만 한 목록, 상대 폴더를 흐리게 표시. 이름순 또는 사용자 순서(같은 목록 안에서 파일을 끌어 놓아 정렬).
  - "최상위에 고정/해제"(오른쪽 클릭): 고정 항목은 모든 보기에서 맨 위(원래 자리에서는 빠짐), 고정 폴더는 현재 보기 방식으로 내용을 보인다. 고정 파일은 규칙과 관계없이 보인다.
- **사용자 지정 파일**(폴더 프로젝트별, 기본 제공 Claude·Codex 포함): 트리 맨 위의 `사용자 지정 파일` 노드에 프로젝트 루트 밖의 파일도 모아 둔다. 프로젝트를 만들면 빈 노드가 기본으로 있다. 시스템 프로젝트와 같은 기능 — 경로 입력 등록(없으면 확인 후 빈 파일 생성, 등록 후 열기), 찾아보기 추가(여러 개), 목록에서 빼기(파일은 그대로), 일반 파일 작업. 비밀 파일도 등록할 수 있으며 자물쇠 표시와 암호화 백업을 적용한다(화면 가림은 화면 공유 모드에서만).
  - 목록은 `projects.json` 항목의 `customFiles`(전체 경로 배열, 비어 있으면 쓰지 않음)에 저장한다. 올바르지 않은 경로가 있는 항목은 원문 그대로 보존하고 불러오지 않는다.
  - 편집 모드(✎)에서 노드에 체크박스가 생기고, 해제하면 일반 모드에서 노드를 숨긴다(`visibility.hideCustomFiles`). 보이는 항목 규칙은 목록 안 파일에 적용되지 않는다.
  - 앱 안에서 이름 바꾸기·이동하면 목록 경로가 따라가고, 삭제한 파일은 목록에 남아 `이름 (없음)`으로 보인다.
  - 메인 메뉴의 등록·추가는 프로젝트 영역에서 선택한 폴더 프로젝트(없으면 시스템 프로젝트) 목록에, "현재 파일을 사용자 지정 파일에서 빼기"는 그 파일이 있는 모든 목록에서 뺀다.
- 경로 표시줄과 툴팁은 보기 방식과 관계없이 항상 전체 경로를 보인다. "트리에서 위치 보기"는 편집 모드 전체 트리로 바꾸고 해당 항목을 선택한다. 트리 조작은 모든 보기에서 실제 경로 기준이다.
- **붙여넣기·복제**: 선택 폴더 → 그 안, 선택 파일 → 그 파일의 폴더, 압축 행 → 클릭한 마디(없으면 사슬의 마지막 폴더), 평면·고정 항목 → 실제 경로. 선택이 없으면 오류 안내. 다중 선택이면 포커스 항목 기준. 같은 폴더에 붙여넣으면 복제처럼 동작하고, 폴더를 자기 자신·하위로 붙여넣기는 막는다. 이름 충돌 시 "덮어쓰기 / 둘 다 유지(번호) / 건너뛰기"와 "남은 충돌 모두에 적용". 덮어쓰기 전 원본을 6절대로 백업한다(비밀 파일도 DPAPI 암호화 백업 후 휴지통 처리). 폴더는 덮어쓸 수 없다. 잘라내기+붙여넣기는 이동(다른 프로젝트로도 가능). Ctrl+D 복제는 `이름 - 복사본.확장자`, `이름 - 복사본 (2).확장자`…로 만들고 새 항목을 선택해 바로 이름 바꾸기(F2). 붙여넣기·복제·이동은 작업 이력에 남아 Ctrl+Z로 되돌린다. 클립보드는 CF_HDROP이라 Windows 탐색기와 양방향으로 복사·붙여넣기 된다.
- 제외 폴더(기본, 설정 가능): `node_modules`, `bin`, `obj`, `.git`, `.vs`, `.venv`, `dist`, `__pycache__`.
- 아이콘으로 파일 종류 구분, 미저장 문서 표시(●), 검증 오류 표시(⚠).
- 파일 시스템 변경은 `FileSystemWatcher`로 트리에 실시간 반영(디바운스).
- 이동·이름 바꾸기·삭제는 **작업 이력**에 기록되어 "되돌리기"(탐색기에서 Ctrl+Z)가 가능하다. 삭제는 휴지통에서 복원.
- 비밀 파일(`.env*`(example 제외), `*.pfx`, `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, `auth.json`)은 자물쇠로 표시(링크는 최종 대상 기준)하고 화면 공유 모드에서 가리며 열기·편집·저장을 허용한다.
- 파일을 열 때 7.0 판별기가 역할·범위를 정하고, 탭 툴팁과 속성 패널에 `역할 · 범위`(예: `settings.json · 프로젝트`)를 표시한다.
- 컨텍스트 메뉴와 문서 탭 메뉴에 "다음 형식으로 열기 ▸ 텍스트/Markdown/설정 폼/에이전트 폼/스킬 폼/자동 판별로 되돌리기"를 둔다. 지정은 파일 경로별로 `%APPDATA%\DotDeck\editor-overrides.json`에 기억한다. 폼이 내용을 해석하지 못하면 이유를 표시하고 텍스트 보기로 연다.

### 7.0 파일 역할 판별
- 파일 이름이 아니라 제품이 설정을 읽는 위치로 판별한다. Claude는 가장 가까운 `.claude` 폴더 기준 상대 경로 → `.claude` 밖 규칙(CLAUDE.md, CLAUDE.local.md, .mcp.json, ~/.claude.json 등) 순서. `.claude`의 부모가 홈(`DOTDECK_HOME`/`--home` 해석 결과)이면 전역, 아니면 프로젝트. `settings.local.json`은 로컬(Git 제외). Codex는 해석된 CODEX_HOME과 `.codex`, 스킬은 `.agents/skills` 기준으로 판별한다(7.5절).
- `.claude` 밖 프로젝트 파일은 "앵커 폴더"(`.claude` 또는 `.git`이 있거나 등록된 프로젝트 루트) 기준으로 판별한다. 앵커가 아닌 폴더의 CLAUDE.md는 "하위 폴더"(필요 시 로드) 범위.
- 규칙은 `DotDeck.Core/Catalogs/<제품>/file-roles.json` 데이터로 관리한다. Claude·Codex·agents 카탈로그를 함께 사용하며, 사용자 덮어쓰기는 `%APPDATA%\DotDeck\catalogs\<제품>\`에 둔다. Codex 스킬 위치 규칙은 `Catalogs/Codex/agents-file-roles.json`에 둔다.
- 파일 내용은 보조 신호로만 쓴다. 기본 제공 프로젝트와 사용자 프로젝트에 같은 판별기를 쓴다.
### agents/*.md (`.claude/agents/` 아래, 하위 폴더 포함)
- 폼: `name`, `description`(여러 줄), `tools`(체크 목록 + 직접 입력, 도구 카탈로그 공유), `model`(opus/sonnet/haiku/fable/inherit/직접 입력) + 본문.
- 검증: frontmatter 파싱, `name`·`description` 필수(`name`이 없으면 Claude Code는 문서로 취급). 파일명과 다르면 정보 표시.
### skills/<이름>/SKILL.md (`.claude/skills/` 아래)
- 폼: `name`, `description` + 본문. 검증: `name`은 선택(없으면 폴더명), 폴더명과 다르면 경고, `description`+`when_to_use` 1536자 초과 경고.
### settings.json (전역/프로젝트/로컬)
- **권한 탭**: 행 = `[allow|ask|deny] [도구(선택+직접 입력, 기본 도구+MCP)] [인수]`. 저장할 때 `도구(인수)`, 인수가 없으면 `도구`. 해석할 수 없는 규칙은 원문 그대로 표시·보존. 도구별 인수 작성법(placeholder·규칙·예시·함께 적용되는 도구, `/path`의 범위별 기준)을 툴팁과 속성 패널에 한글로 표시. 행 추가·삭제·이동, 중복·충돌 경고와 무효 규칙 경고.
  - **인수 형식**(카탈로그 `argumentKinds`, 공식 문서 기준): 명령(Bash·PowerShell) / 경로(Read·Edit) / 도메인(WebFetch, `domain:` 접두어를 칸 밖에 표시) / 에이전트 이름(Agent, 기본 Explore·Plan + 이 범위의 `agents/*.md` 이름 선택) / 스킬 이름(Skill) / 없음(WebSearch 등, 칸 비활성) / 다른 도구 규칙 사용(Write·NotebookEdit → Edit, Glob·Grep → Read) / MCP(인수 대신 서버 전체·모든 도구 `__*`·특정 도구 선택). 기존 규칙도 이 형식으로 나눠 보이고, 형식에 맞지 않는 값은 그대로 보인다.
  - **매개변수 규칙** `도구(매개변수:값)`(deny·ask, 예: `Agent(model:opus)`)은 그대로 표시·보존하고 속성 패널에 설명한다(별도 입력 UI 없음).
  - **경고**(저장은 막지 않음, 행 옆 ⚠/ⓘ 툴팁 + 검증 결과 패널): 괄호 붙은 MCP 규칙, 인수 없는 도구의 인수, `domain:` 없는 WebFetch, 복합 명령(정보), 가운데의 `:*`(정보), Edit deny만 있고 같은 경로 Read deny 없음(정보), allow의 매개변수 규칙, 쓸 수 없는 매개변수(command·file_path·path·notebook_path·url), allow/deny 충돌·중복, 기존 경고.
  - 도구·matcher 메뉴의 "MCP 도구" 그룹에 찾은 서버(`mcp__서버`, matcher는 `mcp__서버__.*`)와 출처 파일 툴팁. "MCP 서버 N개"를 누르면 서버 이름·출처·읽지 못한 파일 목록.
- **훅 탭**: 이벤트 드롭다운(Claude Code 훅 이벤트 전체 + 직접 입력, 모르는 값 보존), 이벤트 설명(실행 시점·matcher 사용 여부·할 수 있는 일·사용 예). matcher는 체크 목록(도구 또는 이벤트별 값, MCP)·전체·정규식(오류는 경고만). matcher를 쓰지 않는 이벤트는 칸 비활성화(기존 값 보존). `type`이 command가 아닌 훅도 보존. command, timeout 열.
- 스크립트 경로 존재 검증은 판별된 루트 기준(`$CLAUDE_PROJECT_DIR`·상대 경로는 프로젝트 루트, `~`는 홈). 해석할 수 없는 경로는 "확인 불가".
- **MCP 서버 탐색**: 사용자·로컬(`~/.claude.json`), 프로젝트(`.mcp.json`), 설치된 플러그인 설정을 읽기 전용으로 파싱해 서버 이름과 출처만 표시. 서버 실행·연결 안 함. 새로고침.
- **범위 경고**: 해당 범위에서 무시되거나 의미가 달라지는 키를 안내.
- 도구·이벤트·키 설명은 `Catalogs/Claude/*.json`(공식 문서 주소·확인 날짜 포함)으로 관리. `%APPDATA%\DotDeck\catalogs\`의 같은 이름 파일로 덮어쓸 수 있다.
- **훅 테스트 실행기**: 이벤트별 샘플 JSON(수정 가능)을 stdin으로 넣어 실행 → stdout/stderr/종료코드/소요시간을 `훅 테스트` 패널에 표시. 10초 타임아웃, 실행 전 확인.
- **환경 탭**: `env` 키-값 표.
- **JSON 모드**와 폼 양방향 동기화. 폼이 모르는 키는 반드시 보존. JSON 오류 시 폼 전환 차단.

### 7.5 Codex 전용 편집기 (승인된 구현 범위, 2026-11-08)
이 절은 HANDOFF의 사용자 결정과 조사 기록을 정식 사양으로 옮긴 것이다. 아직 구현 전이며, 공식 스키마·문서는 각 구현 단계에서 다시 대조한다. 앱 자체는 네트워크를 사용하지 않는다.

#### 경로·파일 역할·보호 정책
- 실제 홈 모드: 절대경로 `CODEX_HOME`을 사용하고, 없으면 `%USERPROFILE%\.codex`. `--home`/`DOTDECK_HOME` 모드에서는 실제 CODEX_HOME을 무시하고 `<home>\.codex`를 사용한다. 테스트용 `--codex-home` 옵션을 제공하며 데이터 폴더 격리를 유지한다.
- Codex 전역 트리에 계산된 가상 노드 `스킬 (~/.agents/skills)`를 둔다. 경로는 해석된 홈 기준이고 프로젝트 목록에 별도로 저장하지 않는다. 실제 사용자 설정은 개발·테스트 중 수정하지 않는다.
- `auth.json`은 비밀 파일로 자물쇠 표시(화면 공유 모드에서 가림)하되 열기·편집·백업을 허용한다. 런타임 데이터는 기본 숨김, `/plugins`와 `/skills/.system`은 출처를 안내한다. 보안 사유로 편집을 잠그지 않는다.
- 기본 숨김 폴더: `/sessions`, `/log`, `/cache`, `/.sandbox`, `/app-server-control`, `/app-server-daemon`, `/packages`, `/thread-writer-locks`, `/tmp`, `/tui-thread-reference-capabilities`.
- 기본 숨김 파일: `*.sqlite*`, `*.lock`, `.sandbox_migration`, `installation_id`, `version.json`, `models_cache.json`, `history.jsonl`, `session_index.jsonl`, `config.toml.bak-*`. 표시 여부와 편집 가능 여부는 분리하며 보안을 이유로 편집을 잠그지 않는다.
- Codex 카탈로그·내장 스키마는 `Catalogs/Codex/`, 사용자 덮어쓰기는 `%APPDATA%\DotDeck\catalogs\Codex\`에 둔다(`schemas\` 아님). 설명·형식·문서 주소·확인 날짜를 데이터로 관리한다.

#### config.toml·TOML 편집
- 승인된 전용 폼 탭: 모델 / 권한·샌드박스 / 프로필 / MCP 서버 / 프로젝트 신뢰 / 기타(고급). 한 줄 설명·현재값·근거가 있는 기본값·선택 목록과 직접 입력을 제공한다. 카탈로그 밖 값은 경고만 하고 보존한다. `[profiles.*]`는 편집하되 최신 Codex는 별도 `<이름>.config.toml`을 사용한다는 안내만 표시한다. 고급 탭은 테이블 단위 트리이며 배열·인라인 테이블은 한 노드로 타입별 편집한다. 모든 쓰기는 TomlEditDocument로 적용한다.
- 사용자 config의 `[projects.<key>] trust_level`을 경로 기준으로 해석한다. 따옴표·구분자·대소문자·Windows `\\?\` 접두어 차이를 고려하고 `project_root_markers`를 반영한다. 문서로 확정할 수 없는 경우 "확인 불가"로 표시한다.
- Tomlyn(추가 승인됨)은 위치·trivia 파싱에만 사용하고, 자체 패처로 값 토큰 범위만 수정한다. 모르는 키·값·주석·기존 따옴표 스타일·BOM·줄바꿈을 보존한다. 새 Windows 경로는 literal 문자열, 여러 줄은 기본 문자열을 사용한다. TOML 1.1 전용 구문은 생성하지 않는다.
- 패치 후 재파싱 검증이 실패하면 저장하지 않는다. 파싱 오류는 줄·열과 함께 표시하고 폼 전환을 막는다. CRLF·BOM·주석·`[projects.'d:\project\dotdeck']`·점 키·인라인 테이블·배열 테이블의 바이트 단위 왕복 테스트가 필수다. 시험 구현이 실패하면 자체 파서로 전환하고 보고한다.
- MCP 서버는 설정 편집만 제공하고 실제 실행·연결하지 않는다. 비밀값 대상: `mcp_servers.*.env`, `http_headers`, `oauth.client_secret`, `model_providers.*.experimental_bearer_token`, 이름에 KEY/TOKEN/SECRET/PASSWORD/PWD/CREDENTIAL이 포함된 값. `*_env_var`, `env_vars`, `env_http_headers`의 변수 이름은 가리지 않는다.
- 비밀값 포함 파일은 DPAPI(CurrentUser) 암호화 백업(ProtectedData 패키지 승인됨), manifest에 `protected: true` 표시, 복원 시 복호화. 기존 Claude settings.json의 env 비밀값에도 같은 보호를 적용한다.

#### 훅·에이전트·스킬·문서·규칙
- `hooks.json`과 config.toml 인라인 훅은 공용 훅 표로 편집하되 원래 표현으로 저장한다. 표현 간 변환은 명시적 메뉴로만 수행하고 두 파일 diff·한 백업 세트로 검토한다. 저장 후 "`/hooks`에서 다시 신뢰 필요" 배너를 표시한다.
- 훅 이벤트·matcher·timeout·종료 코드 설명과 샘플 stdin은 Codex 전용 카탈로그로 관리한다. 테스트는 실행 전 확인, Windows `commandWindows` 우선, 제한 시간·출력 상한·프로세스 트리 종료를 적용하고 실제 Codex와 셸이 다를 수 있음을 표시한다.
- 사용자 지정 에이전트 TOML 폼·템플릿을 제공한다. 덮어쓸 수 없는 키 `sandbox_mode`, `approval_policy`, `model_provider`, `mcp_servers`는 폼에 노출하지 않고 기존 값은 보존하며 경고한다.
- SKILL.md는 기존 스킬 폼에 Codex 검증 프로필을 적용한다. `agents/openai.yaml` 메타데이터 폼과 스킬 비활성화 토글을 제공한다. YAML은 새 패키지 없이 자체 `YamlBlockDocument`로 수정하며 모르는 내용을 보존한다.
- AGENTS.md·AGENTS.override.md는 Markdown 편집기에서 override와 크기 경고를 제공한다. 제품별 검증은 역할의 제품 정보로 분기한다.
- `.rules`는 최상위 `prefix_rule(...)`과 주석만 있을 때 폼으로 편집한다. 그 밖의 구문은 "폼 사용 불가: N행 이유"를 표시한다. 검사는 `codex execpolicy check --pretty --rules <file> -- <cmd>` 미리보기 → 사용자 확인 → 셸 없이 ArgumentList로 실행, 10초 제한.

## 8. 시스템 프로젝트
### 환경변수
- 사용자/시스템 노드를 열면 **표 형태 문서 탭**으로 열린다. 검색, 추가, 수정, 삭제. 변경 전 diff, 변경 내역을 백업 폴더에 JSON으로 기록(되돌리기 가능).
- 이름에 `KEY|TOKEN|SECRET|PASSWORD|PWD|CREDENTIAL`이 포함된 값은 화면 공유 모드에서 가리고 눈 아이콘으로 표시(기본은 평문). 로그·백업 기록에는 모드와 관계없이 평문을 남기지 않는다.
- **PATH 편집기**: 항목 목록, 위/아래 이동, 존재하지 않는 경로·중복 경고.
- 변경 후 `WM_SETTINGCHANGE` 브로드캐스트, "열린 터미널에는 적용 안 됨" 안내.
- 시스템(Machine) 범위는 관리자 권한일 때만 쓰기. 아니면 읽기 전용 + "관리자 권한으로 다시 시작"(열린 문서·레이아웃 복원). 앱 매니페스트는 `asInvoker`.
### 사용자 지정 파일 (이전 이름: 중요 파일, 기타 파일)
- 기본 목록(추가·제거 가능): `%USERPROFILE%\.gitconfig`, `.npmrc`, `.ssh\config`, PowerShell 프로필(`$PROFILE`), Windows Terminal `settings.json`, `C:\Windows\System32\drivers\etc\hosts`.
- 관리자 권한이 필요한 파일(hosts 등)은 환경변수와 같은 규칙. 비밀 파일도 목록에 추가할 수 있으며 자물쇠 표시와 암호화 백업을 적용한다(화면 가림은 화면 공유 모드에서만).
### 권한 보기
- Claude Code 권한은 7절 settings 편집기에서 다룬다.
- Windows 파일/폴더 ACL은 속성 패널에서 **읽기 전용 보기**만 제공한다. ACL 수정 기능은 만들지 않는다.

## 11. AI CLI 연동

### 11.1 목표
DotDeck 안에서 Claude Code CLI(및 Codex CLI)를 실행하고, 사용자가 **경로를 말하지 않아도** 자연어로 지시할 수 있게 한다.
- 예: "열려있는 파일을 논의한 대로 수정해줘", "웹게임 프로젝트에 README 만들어줘", "프로젝트 중 md 파일 몇 개야?", "settings.json 읽고 분석해줘"
- CLI는 **사용자가 선택한 프로젝트들 안에서만** 동작하고, 선택하지 않은 프로젝트와 열지 않은 폴더에는 영향을 주지 않는다 (VS Code에서 프로젝트 폴더로 `claude`를 실행할 때와 같은 범위 개념).
- 사용자는 PowerShell에 경로나 옵션을 직접 입력하지 않는다. **범위는 UI에서 고르고, 명령줄은 DotDeck이 조립한다.**
- CLI 옵션은 기억이 아니라 설치된 버전의 `claude --help`, `codex --help`로 확인해 설계에 반영한다(2026-11-09 확인: Claude Code 2.1.319, codex-cli 0.167.0).

### 11.2 세션 범위
- **주 프로젝트** = CLI 작업 폴더, **추가 프로젝트** = 추가 작업 폴더(Claude Code `--add-dir` 등). 범위 = 주 + 추가 프로젝트 루트의 합집합.
- Claude 전역·Codex 전역 프로젝트: 기본 제외. 선택 시 "전역 설정이 수정될 수 있음" 경고.
- 시스템 프로젝트(환경변수·PATH·중요 파일): 선택 불가.
- 루트 폴더가 없거나 가상 소스인 프로젝트: 비활성 표시.
- 비밀 파일(2.3절 자물쇠 대상)은 컨텍스트·검색 결과에서 제외.

### 11.3 실행 진입점
1. **단일 프로젝트 빠른 실행**: 탐색기 헤더 툴바 / 프로젝트 우클릭 → `이 프로젝트에서 Claude 시작`. 대화상자 없음.
2. **다중 선택 실행**: 프로젝트 영역에서 여러 프로젝트 헤더 다중 선택 → 우클릭 → `선택한 프로젝트로 Claude 시작`. 우클릭한 프로젝트가 주 프로젝트.
3. **세션 시작 대화상자**: `도구 → Claude 세션 시작…` (단축키 지정)
   - 주 프로젝트 드롭다운 (기본값: 활성 문서가 속한 프로젝트)
   - 추가 프로젝트 체크 목록 (이름 + 경로, 11.2 규칙 적용)
   - CLI: Claude Code / Codex
   - 실행 방식: 대화형 터미널 / 명령 실행(비대화형)
   - 옵션: 열린 문서 목록을 컨텍스트로 전달(기본 켬), 이 범위의 이전 대화 이어가기, 프리셋으로 저장
   - 하단 접이식 "명령줄 미리보기"(실제 실행될 명령, 읽기 전용)
4. **일반 PowerShell 터미널**: AI 없이 주 프로젝트 폴더에서 pwsh만 실행.

### 11.4 프리셋과 기억
- 프리셋(이름, 주 프로젝트, 추가 프로젝트, CLI, 실행 방식, 옵션)을 `%APPDATA%\DotDeck\sessions.json`에 저장. 툴바 드롭다운에서 한 번에 실행.
- 주 프로젝트별로 마지막 추가 프로젝트 선택을 기억해 다음 기본값으로 사용.
- 프로젝트 이름·루트 변경 시 프리셋 자동 갱신, 삭제된 프로젝트는 프리셋에서 경고 표시.

### 11.5 실행 방식
**A. 대화형 터미널**
- 하단 `터미널` 패널 탭. Claude·Codex는 셸을 거치지 않고 ConPTY(P/Invoke)로 직접 실행하고 WebView2 + xterm.js(Assets 번들, LICENSE 포함)로 표시한다. 별도 NuGet은 쓰지 않는다. 일반 PowerShell 터미널(11.3-4)은 pwsh가 없으면 Windows PowerShell 5.1을 UTF-8로 초기화해 쓴다.
- 크기 조절 전달, 한글 IME 입력, 복사·붙여넣기, 스크롤백, 여러 세션 탭 동시 실행.
- 탭 제목: `Claude · DotDeck (+웹게임)`. 탭 툴바에 **범위 칩**(누르면 범위 폴더 목록·경로 표시, 프로젝트 추가/세션 재시작).

**B. 명령 실행(비대화형)**
- 프롬프트 입력창 → `claude -p` 계열(또는 Codex 비대화형 실행)로 실행, 출력은 하단 `AI 작업` 패널에 스트리밍.
- 권한 확인에 응답할 수 없으므로 허용 도구를 명시적으로 제한해서 실행. 범위별 대화 이어가기 옵션 지원.

**공통**
- 권한 우회 옵션(`--dangerously-skip-permissions` 등)은 사용하지 않는다.
- 모든 CLI 프로세스는 Job Object로 묶어 DotDeck 종료 시 함께 정리. 실행 중 상태는 상태줄에 표시.

### 11.6 컨텍스트 전달
**1단계 (시작 시 주입)**
- 세션 전용 임시 폴더(`%LOCALAPPDATA%\DotDeck\sessions\<id>\`)에 컨텍스트 문서를 만들어 시작 프롬프트 또는 추가 시스템 프롬프트로 전달:
  프로젝트 이름 ↔ 루트 경로 표, 열린 문서와 활성 문서, 제외 폴더·표시 필터 규칙,
  "이름이 모호하면 후보를 보여주고 물어볼 것", "활성 문서가 속한 프로젝트를 우선할 것".

**2단계 (DotDeck 내장 MCP 서버, 권장)**
- Claude Code가 DotDeck에 실시간으로 묻는 구조. 세션 전용 MCP 설정 파일로만 연결하고, 사용자의 전역 Claude 설정은 수정하지 않는다.
- 도구: `list_projects`(범위 내 프로젝트), `get_open_documents`, `get_active_document`(선택 영역 포함), `find_files(project, pattern)`(DotDeck 필터·제외 폴더 적용, 비밀 파일 제외), `open_in_editor(path)`.
- 연결 방식은 설계에서 비교 후 결정: stdio 브리지 exe ↔ 실행 중인 DotDeck(Named Pipe) vs localhost 전용 HTTP + 세션 토큰. 외부 네트워크 통신은 없어야 한다.
- 모든 MCP 도구는 세션 범위 밖 경로를 반환하거나 열지 않는다.

### 11.7 범위 보호 (경로 대조 가드)
- DotDeck은 세션마다 `scope.json`(허용 루트 목록)을 쓰고, 프로젝트를 범위에서 빼거나 닫으면 **즉시 갱신**한다.
- 세션 전용 설정으로 PreToolUse 훅을 주입해, 파일 도구와 셸 명령의 대상 경로를 `scope.json`과 대조하고 범위 밖이면 차단(deny)한다. 셸 명령은 경로를 확정할 수 없으면 확인(ask).
- 경로 정규화: 대소문자 무시, `..`, 상대 경로, 심볼릭 링크·정션 실제 경로 해석, `\\?\`·UNC 경로 처리.
- 사용자의 기존 전역 훅(`guard_bash`, `protect_files`)은 그대로 함께 동작해야 한다.
- 범위 안이라도 비밀 파일(2.3절 자물쇠 대상, 링크는 최종 대상 기준)에 대한 읽기·쓰기·검색 대상 지정은 대화형·비대화형 모두 차단(deny)한다.
- Codex는 훅 대신 `workspace-write` 샌드박스와 쓰기 루트(`-C`, `--add-dir`)로 보호하고 변경 요약으로 사후 확인한다(읽기 제한 없음, 범위 축소는 재시작).
- 훅 구현 언어(Python 스크립트 vs DotDeck 동봉 콘솔 exe)는 설계에서 비교 후 결정.

### 11.8 파일 변경 반영
1. 실행 전(명령 실행 방식) 또는 세션 시작 시(대화형): 미저장 문서가 있으면 "모두 저장 후 실행 / 취소".
2. 범위 내 열린 문서를 6절 백업 폴더에 **세션 스냅샷**으로 저장.
3. FileSystemWatcher가 변경 감지 → 미저장 변경 없는 문서는 자동 다시 불러오기, 있으면 6절 충돌 대화상자.
4. 실행 종료(또는 대화형에서 사용자가 `변경 검토` 클릭) 시 **변경 요약**: 변경·생성·삭제된 파일 목록 + DiffPlex diff, 파일별 되돌리기 / 전체 되돌리기 / 수락.
5. CLI가 만든 새 파일은 트리에 실시간 반영(2.3절), 선택 시 문서 탭으로 열기.

### 11.9 구조 (참고, 설계에서 확정)
- `DotDeck.Core`: `SessionScope` 모델, 명령줄 빌더(순수 함수, 공백·한글 경로 이스케이프), 범위 검사기, 프리셋 저장소, 컨텍스트 문서 생성기, 스냅샷·변경 요약 로직. 모두 인터페이스 뒤 + 테스트 가능.
- `DotDeck.App`: 세션 시작 대화상자, 빠른 실행 명령, 터미널 패널(ConPTY + xterm.js), AI 작업 패널, 범위 칩, 변경 요약 대화상자.
- 범위 가드 훅, MCP 브리지: 별도 프로젝트 여부는 설계에서 결정.

### 11.10 테스트 (Core, xUnit)
- 명령줄 빌더: 공백·한글·특수문자 경로, 추가 폴더 0개/여러 개, Claude/Codex 분기.
- 범위 검사기: 대소문자, `..` 탈출, 심볼릭 링크·정션, UNC, 범위 축소 후 즉시 차단.
- 프리셋 왕복 저장, 프로젝트 이름·루트 변경 시 갱신.
- 컨텍스트 문서에 비밀 파일·시스템 프로젝트가 포함되지 않음.
- 스냅샷 → 변경 → 되돌리기 왕복.
- 실제 CLI 실행 테스트는 가짜 CLI 실행 파일로 대체.
